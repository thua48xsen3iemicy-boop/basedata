# Исследование: широковещательный домен

Дата проверки первоисточников: 2026-10-26. Этот файл — исследовательский черновик. RFC задают IPv4/host/router семантику; IEEE 802.1Q задаёт контекст bridged networks/VLAN Bridges. Эти уровни нельзя смешивать.

## Краткие выводы

- Под «L2 broadcast domain» в учебном объяснении обычно понимают область канального пересылания, в которой L2 broadcast кадры достигают подключённых участников. В просмотренных доступных официальных материалах IEEE подтверждена область 802.1Q (bridged networks и VLAN Bridges), но точное определение и нормативные условия пересылки из текста IEEE 802.1Q не прочитаны. Поэтому строгую формулировку и исключения нужно подтвердить по доступной редакции стандарта до канонизации.
- IPv4 limited broadcast и network/subnet-directed broadcast — IP-адреса назначения. RFC 1122 связывает IP broadcast с использованием link-layer broadcast на соответствующем канале, однако это не делает IP broadcast и L2 broadcast одним термином.
- Unknown-unicast flooding — отдельное поведение L2 bridge для unicast назначения без известной записи пересылки; точный стандартный алгоритм для IEEE 802.1Q здесь остаётся unresolved, так как соответствующий нормативный текст не был доступен. Не объяснять его через IP broadcast.
- IP subnet, VLAN и broadcast domain не взаимозаменяемы: первое — логическая IPv4 адресация, второе — механизм/идентичность в bridged VLAN контексте, третье — объяснительная граница доставки L2 broadcast. Их взаимное отображение зависит от топологии и настройки. Точные ограничения VLAN/bridge требуют сверки с IEEE текстом.
- RFC 2644 обновляет RFC 1812: получение и пересылка network-prefix-directed broadcasts маршрутизатором по умолчанию должны быть заблокированы; административная настройка может включить опции. Это не распространяется на обычное внутриканальное L2 flooding.

## RFC metadata / применимость

- RFC 919 и RFC 922 отображаются RFC Editor как документы STD 5, оба опубликованы в октябре 1984. В доступных RFC Editor карточках указаны их статусы и тексты; поля Updates/Obsoletes не перечислены. RFC919 §1 сам ограничивает себя до subnet-бroadcast взаимодействий; RFC922 §2/§7 полезен для исторических понятий subnet и limited broadcast.
- RFC1122 — STD 3, опубликован октябре 1989; RFC Editor перечисляет Updates RFC 793 и Updated by RFC 1349, 4379, 5884, 6093, 6298, 6633, 6864, 8029, 9293. В доступных broadcast clauses более поздние updates к этим вопросам не указаны. Errata полностью не аудированы.
- RFC2644 — BCP 34, опубликован августе 1999, Updates RFC1812. Его §3 заменяет конкретные router requirements; применён только для router default.
- IEEE SA показывает IEEE 802.1Q-2022 как Active Standard, superseding 802.1Q-2018, publication date 2022-12-22, перечисляет amendments вплоть до 802.1Qdy-2025 и proposed projects. Утверждения о конкретных clauses 802.1Q не считаются подтверждёнными: PDF не был открыт.

## Vendor-scoped evidence

`CISCO_SWITCH`, “VLANs” and “Transparent Bridging Algorithm”, describes broadcast flooding to other ports in the same VLAN; `CISCO_LEARN`, “Key takeaway”, describes ingress source learning on Catalyst 9000. For a simple single-VLAN topology with forwarding ports, H1 broadcast reaches H2 across the switch; an IP router interface terminates the L2 frame and does not bridge it to H3. This is an explanatory Cisco model with no special filtering, not a verified current IEEE 802.1Q clause.
