# Open Knowledge Curriculum — агентный Git-каркас (v2)

**Статус:** architecture-first prototype (не готовая LMS и не проверенная образовательная программа).

## Идея за 30 секунд

Создаём версионируемую, коллективно поддерживаемую базу **атомарных, проверяемых IT-знаний**. Из них собираются результаты обучения, тесты, учебные маршруты и нормативные планы под различные специальности. Сильные модели проектируют/проверяют; доступные модели исследуют/готовят небольшие порции материала; обычный код проверяет формальные условия. Преподаватель/эксперт утверждает критические изменения. Moodle — внешний потребитель, **не центр архитектуры**.

**Первый фокус:** фундаментальные знания сетевого администрирования; затем Linux, программирование, ИБ и документоведение. Никакого массового импорта тысячи статей до проверки первой вертикальной цепочки.

## Старт для Codex и сообщества

**Главная точка входа Codex: [`CODEX_START_HERE.md`](CODEX_START_HERE.md)**. Это развёрнутое задание на развитие существующей структуры, а не инструкция создать новую. Подробности — `docs/CODEX_ENGINEERING_BRIEF.md`.

1. Откройте `AGENTS.md` (обязательные краткие правила), затем `docs/PROJECT_BRIEF.md` и `docs/ARCHITECTURE.md`.
2. Для изменения в каталоге прочитайте его локальный `AGENTS.md` (Codex не всегда автоматически подхватывает вложенные инструкции при запуске из корня).
3. Выберите **одну** задачу из `work/orders/` или создайте отдельную по `work/ORDER_TEMPLATE.yaml`.
4. Измените небольшой набор файлов строго в своей области ответственности; приложите источники и результат проверки.
5. Запустите `python -m pip install -r requirements-dev.txt` и `python tools/validate.py`.
6. Запустите `python -m unittest discover -s tests -v` при изменении схем или валидаторов. `python tools/coverage.py` покажет демонстрационные пробелы в банке вопросов.
7. Отправьте PR по `.github/pull_request_template.md`.

## Навигация

- `docs/PROJECT_BRIEF.md` — всё, что было задумано, включая будущее развитие.
- `docs/ARCHITECTURE.md` — сущности, зависимости и потоки данных.
- `docs/AGENT_WORKFLOW.md` — модель разделения труда, эскалации, бюджеты контекста.
- `docs/WORKFLOW_STATES.md` — состояния, handoff и конкретные границы параллельных изменений.
- `docs/CODEX_ENGINEERING_BRIEF.md` — развёрнутое проектное ТЗ; не подмешивается в каждый промпт.
- `docs/COMMUNITY_ONBOARDING.md` — простой сценарий входа для внешнего участника с малой моделью.
- `docs/ROADMAP.md` — этапы и критерии готовности.
- `contracts/` — машинно-проверяемые схемы и правила предметной области.
- `knowledge/` — канонические утверждения, объяснения и затруднения студентов.
- `assessments/` — задания для проверки результатов обучения.
- `competencies/` — компетенции и образовательные результаты.
- `standards/` — версии нормативных требований (не равны знаниям).
- `curricula/` — учебные планы, часы, дисциплины.
- `learning-paths/` — педагогические последовательности и повторение.
- `agents/roles/` — инструкции отдельных ролей моделей.
- `.agents/skills/` — короткие пошаговые сценарии для совместимых агентных инструментов.
- `CONTRIBUTING.md` — участие сообщества с небольшими моделями.
- `work/orders/` и `work/handoffs/` — независимые задачи и передачи результатов.
- `integrations/` — запланированный экспорт, Moodle и интерфейсы.

## Предупреждение

Примеры ниже **демонстрационные, не аттестованные**. Наличие ссылок, машинного ревью или успешного CI **не означает** доказанной фактической достоверности. Нормативную корректность образовательных документов утверждает уполномоченный человек. Не вставляйте персональные данные студентов, секреты и закрытые материалы в публичный Git.

## Локальный запуск и создание Git-репозитория

```bash
python -m pip install -r requirements-dev.txt
python tools/validate.py
python -m unittest discover -s tests -v
python tools/coverage.py
# Если папка ещё не является Git-репозиторием:
git init && git add . && git commit -m "Initial knowledge factory architecture"
```

Структурные проверки и 11 тестов выполнены для этого каркаса. `coverage.py` намеренно выявляет непокрытые outcomes в демонстрации; **это не измерение компетентности студентов**. Требуемые документы и роль человека остаются задачами следующих этапов.
