# JSON Schema и проверки

Каждый `unit.yaml`, `questions.yaml`, `learning-paths/*.yaml`, `curricula/*.yaml` и `work/orders/*/order.yaml`, `work/handoffs/*/*.yaml` проверяется по соответствующей схеме. Скрипт `tools/validate.py` дополнительно проверяет известность ID, допустимость путей, связи outcomes/вопросов, совпадение заявленных часов с суммой элементов. **Не** проверяет достоверность материала и юридическую корректность.

Расширяйте схемы через отдельный PR и обновляйте пример/валидатор и документацию миграции. Не делайте неподтверждённых массовых миграций контента.

`work order` и `handoff` структурно связаны ID задачи, ролью и допустимым write scope; пример: `work/handoffs/TASK-DEMO-001/author.yaml`. Статус `done` у задачи не равен `published` у материала.
