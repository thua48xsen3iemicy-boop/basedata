# Контракты и стиль данных

- Формат метаданных: YAML UTF-8; основной контент: Markdown UTF-8; схемы: JSON Schema Draft 2020-12.
- `id` не меняется при смене заголовка. Примеры: `NET.IPV4.CIDR`, `LO.NET.IPV4.CIDR.01`, `Q.NET.IPV4.CIDR.001`. Не кодируйте номер специальности или учебного плана внутри ID знания.
- Пути независимы от ID; переход/переименование пути допустим только с обновлением всех ссылок.
- `status` никогда не повышается моделью до `expert_approved` или `published`.
- `sources.yaml` содержит ссылки, а не копии защищённых публикаций. Оценка достоверности — по утверждению и версии источника, не по числу ссылок.
- Цель результата обучения измерима. Глаголы вроде «ознакомиться» без проверяемого критерия не годятся.
- Каждая оценка ссылается на конкретный `outcome_id`; варианты ответа и объяснение проходят независимую проверку, вычислимое проверяет программа.
- Ветка/PR касается одного bounded work order. Для сопутствующего изменения общего контракта создавайте отдельную задачу.
- Источник данных для будущего экспорта — определённый commit/tag плюс опубликованный manifest, не плавающая main.
- Повторно используйте существующую единицу по ID, если результат обучения совпадает; новые названия тем — это отображение, не клон материалов.
- Примеры демонстрационные, не предназначены для утверждения без экспертной проверки.
