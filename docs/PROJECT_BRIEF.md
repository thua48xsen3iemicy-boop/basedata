# Концепция и требования — конспект исходной идеи

## Цель

Создать открытую для участия сообщества «фабрику образовательных знаний»: с небольших, технически точных и педагогически выверенных единиц знания постепенно вырастает большая общая база; из неё **собираются**, а не переписываются вручную, образовательные траектории, вопросы, учебные планы и обязательные отчётные документы.

## Ключевые положения

1. **Фундамент важнее трендов.** IPv4, двоичная логика, маски, базовые сетевые и вычислительные принципы не требуют постоянной перегенерации только из-за появления новых платформ. Развивающиеся технологии образуют отдельный, более часто пересматриваемый слой. Стабильность не означает невозможности корректировки ошибки.
2. **Одна проверенная сущность — много использований.** Разные дисциплины, специальности, названия тем и редакции стандартов могут опираться на общие единицы знания. Но сходство формулировок не гарантирует эквивалентность глубины или умения.
3. **Учить пониманию, а не чтению страниц.** Первичная сущность — проверяемый результат обучения. Для него хранятся определения, канонические утверждения, несколько способов объяснения, примеры, типовые ошибки/заблуждения, способы коррекции и проверки.
4. **Огромный банк ≠ огромная нагрузка на студента.** Маршруты предлагают необходимые материалы дозированно, проверяют предварительные знания, смешивают вопросы, возвращают темы при забывании.
5. **Автоматизация по ролям.** Сильная модель проектирует карту компетенций и проводит содержательное ревью; небольшие модели ищут источники и готовят материал; программные валидаторы проверяют формальные инварианты; человеческий эксперт одобряет публикацию критичных единиц.
6. **Постепенная сборка.** Ни одна модель не получает весь репозиторий в контекст. Работа делится на независимые, проверяемые задания с краткими контрактами, ветками, PR и артефактами передачи.
7. **Git — источник истины для контента и спецификаций.** Публикации строятся из фиксированных ревизий; изменения нормативов не переписывают задним числом данные о пройденных курсах.
8. **Учебные планы — проекции данных.** Отдельно живут нормативные требования, коды специальностей, версии стандартов, компетенции, результаты обучения, распределение часов и административные шаблоны. Преподаватель проверяет/утверждает, а не набирает вручную повторяющийся документ.
9. **Междисциплинарность.** Помимо сетей/системного администрирования: программирование, информационная безопасность, документоведение, потенциально экономика и новые направления. Участник не обязан быть промпт-инженером: достаточно прочесть инструкции, взять маленькую задачу и предъявить проверяемые результаты.
10. **Не смешивать контент с интерфейсом.** Позднее Moodle/другие LMS получают контент, тесты, пути и результаты по контрактам. Кастомный футуристический студенческий интерфейс — опциональная отдельная подсистема, пока не разрабатывается.

## Статусы качества

`draft` → `machine_reviewed` → `expert_approved` → `published` → `deprecated`.

- `draft`: авторский черновик.
- `machine_reviewed`: один или несколько независимых машинных проходов; всё ещё может содержать ошибки.
- `expert_approved`: явное решение назначенного компетентного человека, имеющего проверяемый след ревью.
- `published`: зафиксированная опубликованная ревизия (после утверждения); отдельный процесс выпуска.
- `deprecated`: сохранено для аудита/исторических учебных планов, но не предлагается в новых маршрутах по умолчанию.

**Важная оговорка:** работа с лицензиями, источниками и конфиденциальностью обязательна, даже когда репозиторий публичный; стандарты/законы имеют юрисдикции и дату действия.

## Не цели MVP

- Полная UI-тема Moodle, визуальные эффекты, личный кабинет.
- Безусловная «гарантия истины» двумя согласившимися LLM.
- Автопубликация без проверок; мгновенная поддержка всех стандартов и профессий.
- Сложный универсальный graph database / vector DB — на старте связей через ID достаточно.
- Гарантированная оценка профессионального умения только по тестам с выбором ответа.
