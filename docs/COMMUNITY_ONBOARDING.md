# Сообщество: участие с маленькой моделью

Внешний участник может помочь найти пробел, собрать первичные источники, улучшить объяснение или разработать один диагностический вопрос. Ему не нужно знать всю репу; он должен понимать свою **предметную область** и не предъявлять машинную самопроверку как экспертную гарантию.

## Минимальный набор чтения

`AGENTS.md` → `CONTRIBUTING.md` → `knowledge/<domain>/AGENTS.md` → конкретный `work/orders/<TASK-ID>/order.yaml` → относящийся к задаче JSON Schema → узлы знаний по `read_ids`. Если задачи нет, открыть issue «knowledge gap», не править десятки файлов наугад.

## Текст для любой доступной модели

> Ты помогаешь пополнить общий открываемый на проверку Git-банк образовательных знаний. Сначала прочти прикреплённые `AGENTS.md`, локальные правила каталога, `order.yaml` и формат unit. Делай **ровно одно небольшое** изменение в допустимых путях. Не выдумывай источники и нормативную обязательность. Если нужный принцип уже есть — предложи ссылку или mapping, а не дублирование. Выпиши фактические утверждения и первичные источники с версией/разделом, а при отсутствии подтверждения поставь вопрос. Не утверждай материал и не переписывай соседние темы. Верни: файлы, краткие findings, команды проверки, открытые вопросы и YAML handoff.

## Пример для экономиста

Участник замечает, что в банке отсутствует объяснение разницы между номинальной и реальной величиной. **Сначала** формулирует проверяемый outcome («различать... на примере...»), находит проверяемый первичный источник/официальную методологию в применимом контексте, заполняет только один согласованный unit в `knowledge/economics/...`. Принципы должны быть технически/методологически корректны для своей дисциплины; экспертизу проводит специалист в экономике, не LLM-рецензент по сетям.

## Что не загружать в репозиторий

Личные данные студентов, экзаменационные секреты, закрытые материалы, чужие тексты целиком, ключи API, личную переписку с моделью, лицензируемые PDF без прав. Публикация чужого содержимого требует предварительного разрешения вопросов лицензирования — см. `docs/LEGAL_AND_SOURCES.md`.
