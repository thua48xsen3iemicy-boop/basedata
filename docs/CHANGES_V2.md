# Изменения относительно стартового каркаса (v2)

1. `CODEX_START_HERE.md`: расширенный рабочий запрос Codex на продолжение существующего репозитория, с критериями, без преждевременной массовой генерации.
2. `docs/CODEX_ENGINEERING_BRIEF.md`: подробная постановка, роли моделей, семантика сущностей, учебные планы, non-goals и открытые решения.
3. `docs/WORKFLOW_STATES.md`: состояния задач и материалов, handoff между моделями и ограничения параллельных изменений.
4. `contracts/handoff.schema.json`: структурный контракт для межагентного артефакта; work-order поддерживает опциональные `depends_on`, `model_tier`.
5. `tools/validate.py`: проверяет handoff/task IDs, имя роли, изменяемые пути, зависимости задач, циклы и безопасность относительных путей. Проверка **не** выявляет реальную конкурентную запись между независимыми ветками.
6. `tools/coverage.py`: счётчик структурного покрытия outcomes вопросами; не меряет педагогическую эффективность.
7. `docs/COMMUNITY_ONBOARDING.md`: minimal context и текст для внешнего участника с малой моделью.
8. `docs/decisions/0001-architecture-baseline.md`: предварительные принятые проектные гипотезы и альтернативы.
9. 11 регрессионных тестов (в первой версии было 5). CI вызывает `coverage.py` только информационно.

## Известные пробелы

- Нет механизма реального экспертного approval и релизного манифеста: `expert_approved` и `published` намеренно запрещены валидатором.
- Факты и источники не доказаны CI; публичные примеры не являются экспертно утверждёнными.
- Нормативная онтология и solver часов описаны концептуально, но не реализованы.
- Scope isolation в разветвлённых задачах пока организационный; глобального scheduler/lock manager нет.
- `tools/coverage.py` сообщает, что 1/4 outcomes имеет хотя бы один вопрос: это демонстрация пробелов, не дефект валидатора.
- Лицензии кода/контента и порядок принятия community PR ещё требуют решений владельца.
