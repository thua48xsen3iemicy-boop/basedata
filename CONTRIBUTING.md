# Как участвовать (человек + любая доступная модель)

Не требуется сильная модель или знание устройства всех каталогов. Можно работать с одним маленьким пробелом в сети, Linux, программировании, экономике, безопасности или документоведении.

1. Найдите конкретный пробел или ошибку. Предложите *проверяемый результат обучения* и первичный источник; создайте issue или отдельный work order по `work/ORDER_TEMPLATE.yaml`.
2. Дайте своей модели `AGENTS.md`, ближайший к нужному каталогу `AGENTS.md`, work order и конкретные примеры схем в `contracts/`. **Не** скармливайте весь репозиторий разом.
3. Модель составляет небольшой diff в разрешённой области. Не надо создавать повторный полный курс, если нужные знания уже есть.
4. Проверьте содержимое и происхождение текста; выполните `python tools/validate.py` и, при изменении валидатора, `python -m unittest discover -s tests -v`.
5. Заполните шаблон PR с ID задачи, ссылками, ограничениями проверки. Машинное согласие недостаточно для экспертного утверждения.

Сначала уточнить лицензии и право приёма контента извне (`docs/LEGAL_AND_SOURCES.md`). Пока это стартовый каркас, а не формально открытый приём материалов на выбранных условиях.

Для новичка удачная первая задача: добавить одно подтверждённое заблуждение студентов или улучшить объяснение без изменения канонического утверждения. Неподтверждённое помечать и отправлять на проверку, а не маскировать красивым текстом.

## Новичкам

В `docs/COMMUNITY_ONBOARDING.md` дан короткий шаблон запроса к доступной модели и пример первой задачи для экономиста или другого отраслевого участника. Никакой обязательной покупки «сильной модели» нет, но качество проверяется по общим правилам.
